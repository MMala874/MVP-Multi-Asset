QUICK START
===========

1. Export MT5 tick data:
   • MT5 Terminal > Tools > History Center
   • Select EURUSD, download full tick history
   • Right-click > Export > Save as data/EURUSD_ticks.csv
   • Columns: time, bid, ask (or datetime, bid, ask)

2. Run edge discovery:
   .venv\Scripts\python.exe scripts/tick_edge_scan.py \
     --tick_file data/EURUSD_ticks.csv \
     --verbose

3. Check results:
   • outputs/summary.json: effect sizes + per-year stability
   • outputs/events.csv: one row per compression event detected
   • outputs/workflow_log.txt: execution summary

4. Interpret decision:
   GO: Effect size consistent across years (>=60%)
       → Proceed to live backtesting
   NO-GO: Effect inconsistent or too small
       → Revisit hypothesis or try new edge


PIPELINE STAGES
================

STAGE 1: TICK DATA LOAD
  Input: CSV (time, bid, ask) from MT5
  Action: Parse timestamps, handle missing ask, drop NaN
  Output: Tick DataFrame with 600K-1M rows

STAGE 2: BUILD MINUTE BARS
  Input: Tick DataFrame
  Action: Resample to 1-min bars, compute tick-level features:
    • tick_count (frequency)
    • micro_range (max_bid - min_bid)
    • spread_mean, spread_std (bid-ask dynamics)
    • realized_vol (std of intra-bar returns)
  Output: Bar DataFrame (424K rows for 2 years)

STAGE 3: DETECT COMPRESSION EVENTS
  Input: Bar DataFrame
  Action: Identify 10+ min blocks where all 3 conditions hold:
    • tick_count < 10th percentile (historical)
    • micro_range < 10th percentile
    • spread_std < 20th percentile
  Output: Event list (11 events in synthetic data, N in real data)

STAGE 4: COMPUTE FORWARD METRICS
  Input: Events list + Bar DataFrame
  Action: For each event, compute post-event (5m/15m/30m):
    • forward_vol (realized volatility)
    • forward_range (price range)
    • forward_return_mean/std/p95 (return statistics)
  Output: events.csv (one row per event)

STAGE 5: COMPUTE EFFECT SIZES
  Input: events.csv
  Action: 
    • Compare post-event metrics to baseline (unconditional)
    • Calculate effect_ratio = post_event / baseline
    • Break down by year for stability analysis
  Output: summary.json with effect_sizes + stability_per_year

STAGE 6: GO/NO-GO DECISION
  Input: Effect sizes + stability_per_year
  Decision: 
    GO if effect_ratio > 1.05 in >= 60% of years
    NO-GO otherwise
  Output: decision.status (GO/NO-GO)


PARAMETER TUNING
================

Compression thresholds (all run on HISTORICAL data, no lookahead):

--tick_count_percentile (default 10)
  What: Events where activity is below Nth percentile
  Lower = stricter (fewer events, more extreme compression)
  Try: 5 (very strict) → 25 (relaxed)

--range_percentile (default 10)
  What: Events where bid range is below Nth percentile
  Lower = stricter (tighter, lower volatility)
  Try: 5 (tight) → 20 (loose)

--spread_percentile (default 20)
  What: Events where spread variance is below Nth percentile
  Lower = stricter (more stable spreads)
  Try: 10 (strict) → 40 (loose)

--compression_duration_min (default 10)
  What: Minimum event duration (in minutes)
  Higher = longer events, more rare
  Try: 5 (frequent) → 20 (rare)

--lookback_window_days (default 2)
  What: Window for historical percentile
  Shorter = more sensitive to recent regime
  Longer = more stable baseline
  Try: 1 (today's data) → 7 (week of data)

Workflow:
  1. Start with defaults
  2. If 0 events: relax tick_count/range/spread percentiles (+5 each)
  3. If NO-GO: check if effect_ratio inconsistent across years
  4. If effect exists but weak: accept NO-GO or try different asset

ANTI-LOOKAHEAD VALIDATION
===========================

✓ All percentile calculations use HISTORICAL data only
  → Compression flags computed from closed bars (no future info)

✓ Forward metrics start AFTER event ends
  → Entry is next bar after compression ends
  → No look-ahead bias in realistic execution

✓ Percentile window is rolling (2-day default)
  → Adapts to market regime naturally
  → Doesn't use global min/max (realistic)

Result: NO lookahead bias. Ready for live backtesting.


NEXT STEPS (IF GO)
===================

1. Freeze parameters from tick_edge_scan.py run
   → Use same --tick_count_percentile, --range_percentile, etc.
   → DO NOT optimize on backtest data

2. Implement operational strategy:
   → Entry: when compression_flag triggers
   → Size: 0.01 lot (or risk percentage)
   → SL: 10-15 pips fixed
   → Exit: time-based (5-15 min) or SL hit

3. Backtest on 5-year data:
   → Check max DD < 5%
   → Win rate doesn't matter
   → Goal: prove edge doesn't disappear post-costs

4. If backtest passes:
   → Paper trade 2-4 weeks
   → Monitor actual slippage vs model
   → If realistic: live trade 1% account

5. Live trading:
   → 4-12 weeks proof of concept
   → Target: monthly Sharpe >= 1.0
   → If passes: scale position size


NEXT STEPS (IF NO-GO)
======================

1. Hypothesis rejection:
   → Volatility compression does NOT precede distribution shift
   → OR shift is too small to trade after costs

2. Options:
   a) Try different asset (GBPUSD, USDJPY, etc.)
   b) Try different time frame (H1/H4 instead of M15)
   c) Try different edge hypothesis (momentum, mean-reversion, etc.)
   d) Revisit tick data quality (gaps? missing ticks?)

3. Learn from failure:
   → Why didn't effect size meet threshold?
   → Was it consistent in any year? (if so, maybe 60% threshold too high)
   → Move on, test new edge

VALIDATION CHECKLIST
=====================

Before declaring GO/NO-GO:

[ ] Effect size > 1.05 or < 0.95 (meaningful change)
[ ] Consistency >= 60% of years (not single-year lucky)
[ ] At least 50+ events in backtest period (enough sample)
[ ] Forward horizons show consistent direction (5m, 15m, 30m aligned)
[ ] No data quality issues (gaps, missing ticks, spreads > 5 pips)
[ ] Backward-only calculation confirmed (no lookahead)
[ ] Parameters frozen before live backtest (no optimization)

If all checked: ready for Phase 1 backtest


TROUBLESHOOTING
================

"No events detected"
  → Thresholds too strict
  → Increase percentiles by 5-10 and rerun
  → Or reduce compression_duration_min to 5

"NO-GO: Effect size not consistent"
  → Effect exists in some years but not others
  → Indicates edge is not robust
  → Try different hypothesis or asset

"ValueError: Invalid frequency"
  → Pandas version mismatch
  → Use freq='1min' instead of freq='60S'
  → (Already fixed in current version)

"MemoryError on large dataset"
  → Dataset too large for available RAM
  → Pre-filter data (e.g., only trading hours)
  → Or split into chunks

"UnicodeEncodeError"
  → Windows console encoding issue
  → Add # -*- coding: utf-8 -*- to script
  → (Already fixed in current version)
