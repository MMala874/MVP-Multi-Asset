WHAT IS THIS?
=============

A rigorous statistical framework to answer ONE question:

"Does volatility compression at tick-level precede a significant change in 
return distribution?"

• If YES (consistent across years) → GO to live backtesting
• If NO (inconsistent or weak effect) → hypothesis rejected, move on


THE HYPOTHESIS
==============

When EURUSD enters extreme volatility compression (10+ minutes):
  • Tick activity drops below 10th percentile
  • Bid range drops below 10th percentile  
  • Spread volatility drops below 20th percentile

→ The distribution of subsequent returns CHANGES

→ IF this change is consistent across multiple years → edge exists

THE 6-STAGE PIPELINE
====================

Input: MT5 tick CSV (bid/ask)

Stage 1: LOAD TICKS
  ↓
Stage 2: BUILD 1-MINUTE BARS (with tick-level features)
  ↓
Stage 3: DETECT COMPRESSION EVENTS (10+ minutes, all 3 conditions)
  ↓
Stage 4: COMPUTE FORWARD METRICS (5m/15m/30m post-event)
  ↓
Stage 5: COMPUTE EFFECT SIZES (post-event / baseline)
  ↓
Stage 6: GO/NO-GO DECISION (effect > 1.05 in >= 60% of years)

Output: events.csv + summary.json


════════════════════════════════════════════════════════════════════════════════

DECISION LOGIC
==============

GO Decision:
  • Effect size (ratio) > 1.05 (or < 0.95)
  • Observed in >= 60% of years
  • NOT a single-year lucky event
  → Action: Proceed to Phase 1 backtest

NO-GO Decision:
  • Effect size close to 1.0 (< 1.05)
  • OR inconsistent across years (< 60%)
  • Edge is too weak or unstable
  → Action: STOP, try new hypothesis

PARAMETERS (TUNING)
===================

All run on historical data (no lookahead):

--tick_count_percentile (default 10)
  Lower = stricter (fewer events)
  Try: 5-10 (strict) or 20-25 (loose)

--range_percentile (default 10)
  Lower = tighter price range
  Try: 5-15 (tight) or 20-30 (loose)

--spread_percentile (default 20)
  Lower = more stable spreads
  Try: 10-15 (strict) or 35-40 (loose)

--compression_duration_min (default 10)
  Higher = longer events
  Try: 5 (frequent) or 20 (rare)

Tuning workflow:
  If 0 events: increase percentiles by 10 and retry
  If NO-GO: check year consistency in summary.json
  If effect too small: accept NO-GO (not profitable)
